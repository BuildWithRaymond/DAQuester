# DAQuester 1.1.1 — Easier conversations and simpler maintenance

Quest conversations now approach the nearest free tile beside an NPC when the
usual tile is blocked or occupied. Two characters can approach without competing
for one exact spot. Open dialogs also survive same-map refreshes, keeping the
insignia discovery page available to read.

The supported client launcher skips the agreement using the two established
DAOrganizer branches before resuming a newly created, validated client. Existing
clients and game files on disk are untouched. Synthetic tests cover early and
fragmented lobby notices, redirects, immediate lobby disconnects and replacement
connection identity; live native-client verification remains pending.

DAQuester now has its own application icon. The Developer tools panel has been
removed. Diagnostics remain in `Data/diagnostics.log` and the control bridge;
calibration and connection settings remain accessible through the bridge and
Data folder. Sanitized replays save automatically on disconnect and exit.

For contributors, checkpoint stores share one durable JSON writer, packet tests
are consolidated, and the three-minute drought-test sleep is replaced with
repeated synthetic patrols. Movement timing checks use send timestamps and
explicit gates. Automated UI render matrices and the headless dependency are
removed, while account, planning, ownership and shutdown regressions remain.
Documentation screenshots are optional. CI packages its tested build instead
of compiling it again, retaining payload, checksum and updater verification.

Saved data formats, quest policies, cooldowns, observed-evidence boundaries,
generation isolation and checkpoint recovery remain compatible. Update checks
stay optional and off by default; download and installation require separate
actions. No tests operate real characters.

Download **DAQuester-win-Setup.exe** or **DAQuester-win-Portable.zip**. Both include
the .NET runtime. Keep the complete portable folder together. Game files are
not included. Current evidence limits are documented in
[validation](https://github.com/BuildWithRaymond/DAQuester/blob/v1.1.1/docs/validation.md).
