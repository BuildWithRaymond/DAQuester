# DAQuester 1.1.0 — A new desktop journal

DAQuester now runs on Avalonia, with a carefully rebuilt dark interface for your
Dark Ages journeys. Deep navy and slate surfaces, warm gold, clear type and crisp icons
keep the focus on your characters and their next quest.

The Quest Planner brings the library, your character's queue and current progress
together. Search the full catalog, read the requirements, and arrange automatic
quests with drag-and-drop, move buttons or keyboard shortcuts. Ready and Choices
rows carry a restrained teal green tint; finished legend goals say Completed, and
blocked quests explain what needs to change.

Characters has a separate Launch button for each saved account, masked password
editing, remembered levels and own legend marks. Facts that have not been observed
stay visibly unknown. With no saved characters, Launch opens a blank client for
manual sign-in. Run History keeps verified receipts readable, and Settings
puts the game client, updates and optional Developer tools in one consistent place.

Your existing settings, encrypted logins, queues, journals, character memory and
checkpoints continue to use the same Data folder. The quest engine and protocol
services remain in place, including cooldowns, repeat policies, final-dialog
cleanup and generation isolation. Pending submissions can still reconcile when
the character's recorded legend or level blocks another new attempt.

Update checks remain optional and off by default. Checking, downloading and
installing are separate actions. Install and exit requires finished automation,
disconnected sessions and closed DAQuester-launched game clients.

Download **DAQuester-win-Setup.exe** for an installation, or
**DAQuester-win-Portable.zip** for a portable folder. Both include the .NET runtime.
Keep the complete portable folder together. Game files are not included.

This migration is verified with isolated synthetic sessions, presentation and
quest regressions, actual rendered screenshots, keyboard and pointer input, and
release/update compatibility checks. These checks never operate real characters
or replace the remaining live-evidence limits documented in
[validation](https://github.com/BuildWithRaymond/DAQuester/blob/v1.1.0/docs/validation.md).
