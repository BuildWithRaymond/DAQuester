# Altar Worship eligibility across resume

The player confirmed that a character who passes the class requirement stays
eligible for the rest of this journey. Class and reward consent are entry checks,
not requirements to refresh after every reconnect or offering.

Persist a successful initial eligibility check with the character's quest
checkpoint. Existing verified offerings or accepted no-legend reward consent
also establish eligibility, so upgrading does not block earlier progress. Do not
infer eligibility from the level, an unverified submission or elapsed time.

Desktop preparation, queue dispatch, item preparation and the runner use the
same saved eligibility rule. New journeys without it still read the class and
require applicable reward consent. Identity, connection generation, resources,
offering timing and uncertain-transaction reconciliation keep their current
guards. Offering receipts and due times are not rewritten by resume.

Final reward verification still reads fresh own legend and ring evidence. Choose
its reward branch after the profile reply, because a resumed session may not
have a class value before that reply.

Synthetic regressions cover existing accepted and priest-family continuations,
one initial check across reconnect, initial missing class or consent, preserved
offering schedules, and fresh final reward proof. Run both complete xUnit suites
and the release packaging, verification and update compatibility checks. No live
character operation or client restart is part of this work.
